# 主线场景接线维护记录

本次按审阅者确认的统一修复计划执行。源数据为 `data/scenes.json` 与 `data/events.json`，引擎为 `src/events.js`；回归见 `tools/test-main-route.mjs`。本文件描述当前行为与接线约定。

## 接线约定

1. **先切景，再播到达描写**：任何进入新场景的路线都必须先执行 `changeScene`，目的地描写（“一进入车厢……”“你踏进2号车厢。”）必须落在新背景上。
2. **出发文字留在出发场景**：推门、过门、起步这类句子属于出发场景，不因为下一句要切景而提前切。
3. **点击目标必须语义匹配**：场景热点的 `clickEvent` 指向的事件，其内容与状态修改必须属于该场景；门类热点优先复用 `E_GO_<出发>_<到达>` 命名。
4. **同一段落只播一次**：进车厢类检定用独立旗标闸门；到过一个场景的记录（如 `crew_met`）不因路线不同而缺失。
5. **进车先点门，剧情不许代劳**：从一节车厢进入下一节车厢必须由玩家点击门热点（`door_<出发>_<到达>`）触发；剧情事件不得用 `changeScene` 直接替玩家完成跨车厢。否则玩家没有机会在门前做选择——3号→2号的门同时是里世界入口，一旦由剧情自动进车，一条主要支线就会被整段跳过。
