# 三天最低可交付计划

当前压缩包已经实现了“极简可运行框架 + 粗糙示例”。下面三天不再重写架构，重点是让组员接入并用真实内容替换占位内容。

## 第一天：冻结约定并接入第一批素材

- 你：向两名程序员讲清 `Event = actions[]`、Scene Object 只连接 `clickEvent`、自定义动作白名单三个约束。
- 场景程序：用真实 6 号车厢背景替换示例 SVG，放入 2–3 个单独切图的可点击物。
- 剧情转换：只转换一小段能走通的事件，不追求全剧本。
- 验收：打开 `index.html`，真实场景可见，点击物能进入对应事件。

## 第二天：跑通一条真实分支

- 你：根据真实内容补缺失的通用 Action，但每新增一种都先确认至少会复用两次。
- 程序员 A：接入检定规则与结果表现。
- 程序员 B：接入物品栏的最小展示和一个物品状态变化。
- 场景程序：验证获得物品后贴图隐藏、切换车厢后状态仍保留。
- 验收：一条“调查 → 获得物品/改状态 → 检定 → 分支 → 换场景”链路完整。

## 第三天：稳定、文档和提交样例

- 用 `npm run check` 阻断重复 ID、悬空引用和 JS 语法错误。
- 从新浏览器会话测试开始、保存、读取、重开。
- 删除仅用于调试的日志，确认所有素材路径大小写一致。
- 保留一份最小示例事件，作为组员复制模板。
- 将完整网站目录压缩为老师要求的 `.rar`；压缩前不要遗漏 `data/compiled-game-data.js`。

## 明确推迟

多存档槽、像素级不规则命中、复杂动画编辑器、Markdown 自动解析器完善版、通用 NPC 系统都不进入三天目标。
