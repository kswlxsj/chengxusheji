# 剧本转换 skill 使用教程（从触发后开始）

> 适用对象：在 webGame 仓库内操作本转换 skill 的人与执行 agent（两边对照阅读）。
> 前置：skill 已被触发（你已说出类似“用剧本转换 skill 把 X 剧本转一下”并得到回应）；**本教程不涉及如何安装/如何触发**。
> 权威规则：`skills/script-to-game-data/SKILL.md`（红线、闸门与唯一事实源，AI 工作流树）与 `skills/script-to-game-data/conversion-rules.md`（全部细节：命名 §10、白名单 §11、审查清单格式与路径 §13）。本教程是“走一遍”的手把手指引，冲突时以 SKILL.md 与 conversion-rules.md 为准。

## 0. 总览：一次完整转换的三段闸门

```text
你指定输入文件
   ▼
[候选阶段] 解析剧本 → 候选JSON(不落盘) + 审查清单落盘(分钟时间戳) + 隔离编译验证
   ▼
闸门 1（决策闸）→ agent 停下；你在清单上逐条勾选答复（同意 / 需要调整 / 本次跳过）、逐行指定素材后回复“已修改，继续”
   ▼
闸门 2（改动方案确认闸）→ agent 摆逐文件 diff 草稿，你逐文件确认
   ▼
[landing] 写入白名单 JSON → 真实 npm run compile（报错即回滚修复）
   ▼
闸门 3（终审闸）→ 你看 diff 与编译结果；通过后 agent 才 git 提交
```

任何闸门未获你明确批准，agent 必须就地等待，不得跳过闸门，也不得把“清单审阅”与“写入数据”合并成一步。

---

## 1. 第 0 步：先把“输入”说清楚（你触发后的第一次对话）

agent 会按规矩**先确认输入**，你不给文件它不会开工：

- 你只需回答输入文件路径（一个或多个），例如：`把 Assets/Text/剧本.md 转一下`；
- 多文件时顺带说明关系：连载（第 1 卷、第 2 卷？）、不同版本（以哪份为准？）、各自独立（分属不同剧本？）；
- 如果你忘了给，agent 会列出候选并问你“用哪个 / 还是放弃”，你选一个即可。

agent 校验失败（文件不存在、不是 UTF-8、内容不是剧本）时会停下报告，不会硬转。

## 2. 候选阶段（agent 自动完成，你不用干预）

agent 依次做（顺序详见 SKILL.md 工作流）：

1. 只读注册表快照：`data/attributes.json`、`data/skills.json`、`data/items.json`、`data/scenes.json`、`data/events.json`；
2. 按 `conversion-rules.md` 语法表逐事件解析，产出**候选 JSON 片段**（默认不写盘，用于与你确认）；
3. **审查清单落盘**：复制空白模板 `skills/script-to-game-data/templates/review-checklist-template.md` 并替换占位符，生成 `Game/docs/conversion-reviews/review-checklist-YYYY-MM-DD-HHmm.md`（目录固定、时间戳精确到分钟、每次新建不覆盖；示例：`review-checklist-2026-09-04-1849.md`）。清单含三部分：**人话提问**（请你判断的事）、**素材指定区**（候选依赖的素材）、文末**执行台账**（agent 内部用，你可忽略）；
4. **隔离编译验证**：把 `Game/` 复制到系统临时目录 → 注入候选 → 跑 `node tools/compile-data.mjs` → 断言通过后删除临时目录（真实 `data/` 全程不动）。

想提前熟悉产物长什么样？看 `skills/script-to-game-data/samples/`：`sample-input.md`（节选原文）、`sample-output.json`（候选事件）、`sample-notes.md`（逐条解释每个语法怎么映射、哪些进了清单）。

## 3. 闸门 1：你的决策环节（直接在清单文件上作答）

候选阶段结束，agent 会停在第 1 闸门并告知清单路径与待办概览（N 条提问、M 行素材）。**清单面向你写得通俗易懂**——你打开文件作答即可，不用在对话里复述，也不需要懂任何转换技术细节（agent 的类别、内部命名等全部收在文末「执行台账」，标注仅供 agent 用）。

清单结构（空白模板见 `skills/script-to-game-data/templates/review-checklist-template.md`，格式见 `conversion-rules.md` §13）：

- **先读这里**：一段“2 分钟上手”说明（怎么勾选、怎样才算完成）；
- **一、请你判断的 N 件事**：每条提问都用普通人能懂的话写成，固定结构：
  ```
  Q1 事件 E-005 灵感失败时，E-006 的 SAN 损失要更重吗？
     剧本原文：……（原句短引）
     我的处理：我把事件 E-006 按上一步检定成败拆成损失不同的两版……
     请你判断：失败线损失 1d4，符合你的原意吗？
     建议：……｜若按建议：……｜若本次跳过：……
     我的答复：☐ 同意　☐ 需要调整　☐ 本次跳过
     说明：（需要调整时写替代方案；跳过时写去向）
  ```
  作答就是**勾一个词**；勾「需要调整」请在「说明」写清替代方案；勾「本次跳过」建议写明去向（如“交框架组 / 随下批”）；
- **二、素材指定区（M 行）**：候选要正常运行所依赖的素材（场景背景 / 物件贴图 / 物品图标），每行四选一：
  - **沿用**：确认使用既有素材文件；
  - **新建**：由你给出文件名 + 内容/风格描述，agent 只登记引用、不自己生成文件；
  - **委托占位补位**：你不想现在出素材，委托 agent 在 `assets/` 生成**简单占位 SVG** 并自行命名（仅纯色/几何示意，正式素材日后替换；新增文件会列入闸门 2 diff 给你确认）；
  - **本行暂缓**：注明影响——依赖它的候选事件不落地。
  **每行必须有结果；留空 = 闸门未过，agent 会停下追问。**
- **补充说明**：自由区，可用 `#Q1` / `#M1` 引用条目写整段话；
- **收尾**：完成后按固定口令回复（见下）。

答完回复 agent「**已修改，继续**」：agent 先校验“全部提问有答复 + 素材每行有结果”，不满足会停下逐条追问；满足后按你的答复执行（同意 → 按建议；需要调整 → 按「说明」的替代方案；本次跳过 → 不落地并记录），并在文末台账更新状态、对执行过的条目追加“→已落地（日期）”标记——**绝不改写你写下的内容**。

三种收尾（固定口令）：

- 全部处理完且想落地 → 「**按清单落地**」进入闸门 2；
- 想先调整转换本身 → 「**先修订候选 / 清单**」，agent 改完重新停在闸门 1；
- 先不落地 → 「**先不落地**」，仓库只留清单与候选，`data/` 零改动；
- 想暂停 → 「**先等等**」，agent 就地停止。

> 提示：约定类问题（如 `SAN X/Y` 记法的统一解释）若在历史清单中已被你批准过，会合并成一条「沿用上次已批准的约定？」确认，不会逐条重复问你。

## 4. 半路提问：agent 什么时候会打断你（阻断情形）

这些不是流程故障，是 skill 的规矩（conversion-rules.md §16）——碰到就停下问你，**不猜**：

- 跳转目标不存在：如“（→E-01X）”查无此事件 → 你确认是笔误还是漏写事件；
- 编号冲突：来源编号和既有 events.json 或另一输入文件撞车 → 你给命名空间或改编号；
- 分支归属无法判定、内容语义不明 → 你拍板；
- 落地要求超出白名单或要删除既有内容 → 你要先明确授权；
- 表格/特殊结构无法映射 → 转人工，别硬编。

示例：
> agent：（停在闸门 1 前）事件 E-009 不在本批转换范围，但 E-005 的“放弃前进”通向它，接线无法闭合（清单 Q5）。请你决定：随 E-009 下批一起落地 / 本批先放一个临时收尾 / 其他？
> 你：清单 Q5 勾「需要调整」，说明写“本批先放一个'故事待续'的临时收尾事件，E-009 批次落地时再改接”。

## 5. 闸门 2：逐文件确认改动方案

你批准落地后，agent 先把 **diff 草稿**摆出来，而不是直接写：

- `events.json`：检查点——只追加新命名空间事件；旧条目零改动；占位行位置符合你批准的方案；无悬空引用；
- `scenes.json` / `items.json` / `meta.json`：只在你要改时才出现 diff，且每个改动都要你单独点头（涉及坐标/素材/物品注册等设计输入，skill 无权自作主张）。

你可以逐文件说“events 的追加块确认”“scenes 这版不改”“items 的钥匙 id 改成 crew_keys 再确认”。全部确认后 agent 才执行写入。

## 6. landing：写入与真实编译

- agent 把候选写入白名单文件（保持 2 空格缩进风格）；
- 在**真实仓库**执行 `node tools/compile-data.mjs`（等价 `npm run compile` 的核心）；报错即回滚修复重跑，不允许蒙混过关；
- 如需跑测试可再执行 `npm test`（视改动面）。

## 7. 闸门 3：终审与提交

写入并编译通过后，agent 汇报：改动文件清单、diff 摘要、编译输出、审查清单状态。你终审：

- 满意 → 说“可以提交”；agent 按仓库规范做**中文、原子、详细**的 git 提交（示例：`feat(skills): …`、`docs(剧本): …`）；
- 不满意 → 指出问题，退回闸门 2（改方案重写）。

注意：即使 agent 已写盘，**git 提交仍以你的终审为前置条件**；你随时喊停，agent 就地等待。

## 8. 一次成功跑完，你应该拿到什么

- 一份审查清单：`docs/conversion-reviews/review-checklist-<时间戳>.md`（本次转换的决策台账：人话提问作答 + 素材指定 + 执行台账）；
- （若你批准落地）白名单 JSON 的追加 diff 与真实编译通过结果；
- 一次（或多次）中文原子 git 提交记录；
- 输入剧本文件原样未动；`data/attributes.json`/`skills.json`/`schemas/`/`src/`/`tools/` 等全程未被写。

## 9. 常见问题（FAQ）

**Q：审查清单会不会把旧的覆盖掉？**
不会。文件名带分钟级时间戳且每次新建；同名剧本再转会得到一份新文件。要修订旧清单，需你明确指定文件，agent 才会在原文件增量修改并在文件头注明修订记录。

**Q：除了勾选「我的答复」和素材行，清单里我能随便写吗？**
可以。「说明」「补充说明」都是给你自由书写的区域（引用条目用 `#Q1` / `#M1`）。agent 只认勾选词与固定口令（同意 / 需要调整 / 本次跳过、沿用 / 新建 / 委托占位补位 / 暂缓、已修改，继续 / 按清单落地…），其余文字一律视为说明；它不会改写你写下的内容，只会对执行过的条目追加“→已落地（日期）”标记。

**Q：候选 JSON 为什么不写盘？**
候选是“未定稿的半成品”，写进 `data/` 会造成既有内容区与未定内容的混乱。它只用于与你确认；确认后经闸门 2 才作为 diff 进入白名单文件。

**Q：清单里的“占位行”是什么样，怎么变成真规则？**
形如事件里一条 `{ "type": "dialogue", "text": "（检定：医学）" }`——原文照录、表示此处待人工落地。落地时你给出规则（如映射到某属性+修正，或注册技能），agent 替换为真正的 `check`/其他动作并删除占位行。

**Q：和既有 events.json 里那套 E_CHECK_* / 演示事件什么关系？**
skill 默认只增不改不删，也绝不自动判断旧区段去留；关系处置（保留/替换/清理/成为主线）在落地前由你决定（清单提问区会有相应一条，勾选或调整即可）。

**Q：为什么会有 `actions: []` 的空事件？**
“检定某侧无事发生、事件自然结束回场景”时的端点约定（转换规范 §6.2）；编译器和运行时都接受。详见样例 `E_006A_END`。

**Q：隔离编译和真实编译有什么差别？**
隔离编译在临时副本里跑，验证“候选合入后全量无悬空/无重复”；真实编译在落地写盘后跑。先隔离是为了在动真实数据前发现问题。

**Q：多文件剧本怎么办？**
先说明关系。连载用同一编号体系时把编号冲突交给你的命名空间决定；版本并列以你指定为准；互相引用跨文件的跳转视同悬空询问。

**Q：什么时候会跑 `npm run check`？**
落地修改涉及测试面时，终审前跑一遍更稳妥；只出清单不落地则不需要。

## 10. 出问题时的兜底

- 不确定就问 agent，让它引 SKILL.md/转换规范对应小节；
- 任何一步你想反悔：在闸门 1/2 直接说“退回上一步”，agent 会还原候选或回滚已写入改动（写入未提交前均可回滚到工作区原状）；
- 记住三条底线：**不写注册表、不改 schema/运行时、不发明数值**——清单里永远能找到“为什么这里没自动转”的答案。
