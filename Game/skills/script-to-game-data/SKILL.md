# 剧本 → 游戏 JSON 转换 skill

本 skill 服务于本仓库的“事件驱动剧情框架”（见 `Game/README.md`），最终目的是把编剧写的剧本（Markdown 文本）转成框架数据 JSON。执行原则：**保守、可控**——只产出**候选 JSON 与审查清单**，供人工审阅后再落地；不做数值设计，不删改原文。

- 规则细节：见同目录 [`conversion-rules.md`](conversion-rules.md)（必读）。
- 命名、路径与白名单常量：见同目录 [`conversion-rules.md`](conversion-rules.md) §10/§11/§13（无独立配置文件）。
- 工作示例：见同目录 [`samples/sample-notes.md`](samples/sample-notes.md) 及配套样例文件（`sample-input.md`、`sample-output.json`）。
- 空白清单模板：见同目录 [`templates/review-checklist-template.md`](templates/review-checklist-template.md)。

## 硬红线（贯穿全程，违规即失败）

- 只允许输出到白名单 JSON（见 `conversion-rules.md` §11）；`attributes.json`、`skills.json`、`schemas/`、`src/`、`tools/`、`compiled-game-data.js` 永不写入；`assets/` **默认不写**，允许两类**新增**（见 §13.5）：审阅者勾选「委托占位补位」生成的占位 SVG；从仓库根源目录 `Assets/` 按命名检索命中后复制的图片副本。**源目录 `Assets/` 严格只读**（仅允许读取与复制，禁止移动/删除/改名/编辑/写入）；`assets/` 既有文件永不改动。
- **只增不删改**：不删改、不重写剧本原文词句；只做格式清洗。JSON 候选是“部分派生物”——无法无歧义落地的内容一律不进入 JSON，只进审查清单，绝不编造替代文本或数值。
- **不设计数值与规则**：不发明修正值、骰面、属性/技能、怪物数值、坐标；检定对象只允许直接命中的已注册属性；骰子参数只从原文直译。
- 凡自动推断（拆分、合流、旗标、跳转接线）必须逐条以类别 A 记入执行台账（`conversion-rules.md` §13），并在正文为需要你拍板者生成一条人话提问。
- 悬空跳转目标、ID 冲突、无法辨识的结构 → 停止并询问，不猜测。

## 阶段一 · 候选转换（candidate：只产出，不写 `data/`）

> 本阶段结束于“闸门 1”。整个过程任何写 `data/` 的动作都不允许。

### 1. 确认输入

#### 索取
- 向用户确认输入文件：一个或多个 Markdown 剧本文件的路径（仓库内相对路径或绝对路径均可）。

#### 未指定 → 停下询问
- 用户未指定时：暂停并询问，允许给出候选文件清单与“放弃”选项；不得自行默认仓库内某个文件、不得沿用上次输入。

#### 校验
- 文件存在、可读、UTF-8 文本；内容确实为剧本正文（含“事件”编号类结构）。校验失败 → 停下报告，不硬转。

#### 多文件与冲突
- 多个文件时确认其关系（顺序连载 / 不同版本 / 各自独立）；关系不明或事件编号冲突 → 暂停询问。

#### 只读准备
- 读 `conversion-rules.md`；只读快照 `data/attributes.json`、`data/skills.json`、`data/items.json`、`data/scenes.json`、`data/events.json`。
- 转换过程中不得修改输入文件。

### 2. 逐事件解析与转换

#### 可直译 → 生成候选事件片段
- 事件 ID 用 `conversion-rules.md` §10 的模板（默认 `E_0NN`，连字符转下划线、保留零填充）；与既有数据 ID 冲突时停止询问。
- 叙述 / 台词 → `dialogue`；说话人行 → `speaker`；选择 → `choice`；命中已注册属性名的检定 → `check`（§6.1）；SAN 记法 → 按 §7 直译；合流与前置变体拆分见 §4.2/§8。

#### 不可直译 → 原文占位行 + 登记清单条目
- 技能检定、%修正、或组合、对抗、×2、自动成功、物品获得、跨路径条件、纯舞台指令等：在事件流当前位置放“原文整行占位”`dialogue`（§9），分支/条件原文整块不进 JSON，只按类别记入执行台账（`conversion-rules.md` §13）并在正文为需要你拍板者生成人话提问。

#### 阻断情形（§16）→ 停下询问，不猜测
- 悬空跳转目标；ID 冲突；分支归属无法判定；结构无法辨识。

### 3. 生成审查清单（闸门 1 产物）

#### 复制模板并替换占位符
- 复制 `templates/review-checklist-template.md`，替换全部 `{{…}}` 占位符。

#### 内容三部分（面向审阅者，技术细节一律封装）
- **一、人话提问（Q）**：凡需要审阅者拍板处（推断认可、检定/物品/条件如何落地、文本疑点等）生成一条易懂提问——剧本原文短引 + “我的处理”（一句人话）+ “请你判断” + 建议 + 按建议/若跳过的后果；**一条一问**。类别字母、候选事件 ID、命名/接线等内部行话不进正文（放执行台账）。
- **二、素材指定区（M）**：盘点本批候选 JSON 的全部素材依赖（场景背景图 / 物件贴图 / 物品图标，含 `changeScene` 引用的场景、转换时推断占位的素材）。盘点时**先在仓库根源目录 `Assets/` 按文件名检索可用图片**（只看命名、不读内容；`Assets/` 只读），命中则**复制到 `assets/` 并自行命名**、状态记为「已存在（复制自 …）」，未命中再标 缺失 / 推断占位；逐行标注素材类型、状态三态与所需形态（`conversion-rules.md` §12/§13.5）。**每行须审阅者显式结果（沿用 / 新建 / 委托占位补位 / 暂缓并注明影响）才过闸**；「委托占位补位」授权 agent 生成简单占位 SVG（§13.5）。
- **三、附录 · 执行台账**：按编号映射 {剧本位置 / 类别 / 内部引用（候选、命名、接线）/ 落地动作 / 落点文件 / 用户答复 / 状态}（§13.1/§13.2），仅供 agent 定位与留痕。

#### 落盘位置与命名
- `Game/docs/conversion-reviews/review-checklist-YYYY-MM-DD-HHmm.md`；目录固定、时间戳精确到分钟、每次转换新建文件、不覆盖旧文件（见 `conversion-rules.md` §13）。
- 清单保持精简、面向审阅者友好：先读说明 → 提问作答 → 素材指定 → 补充说明 → 收尾口令；约定级条目按 §13.6 降频（历史已批准则合并为一条“沿用”确认）。

### 4. 隔离编译验证

- 把 `Game/` 整体复制到系统临时目录，注入本次候选（必要时注入隔离占位事件与示例场景），运行 `node tools/compile-data.mjs`，断言编译成功且无悬空引用，随后删除临时目录。
- 失败即视为转换缺陷：修复候选后重跑；真实 `data/` 全程不被写。

## 阶段二 · 闸门 1 决策闸（candidate 结束点）

> 不可跳过、不可与写盘合并；清单仍是人与 agent 之间唯一的决策台账，但**正文只面向你呈现人话提问 + 素材指定**，agent 内部逻辑（类别、命名、接线等）收在文末执行台账，你无需阅读、也无需懂任何转换行话。

### 停点与汇报
- agent 停止，告知清单路径与待办概览（N 条提问、M 行素材）。

### 你在清单上作答（不需要任何技术知识）
- 每条提问勾选「我的答复」：**同意** / **需要调整**（请在「说明」写替代方案）/ **本次跳过**（建议在「说明」写清去向，如“交框架组 / 随下批”）。
- 每行素材在「你的指定」给显式结果：**沿用**（既有素材）/ **新建**（文件名 + 内容/风格描述）/ **委托占位补位**（简单占位 SVG 由 agent 生成、自行命名，落在 `assets/`）/ **本行暂缓**（注明影响——依赖它的候选不落地）。**留空 = 闸门未过**，agent 会停下追问。
- 可在「补充说明」自由书写（用 `#Q1` / `#M1` 引用条目）；agent 不改写你写下的任何内容。

### agent 重读校验与执行
- 你回复“已修改，继续”后，agent 重读文件并**先校验通过条件**：全部提问有答复且素材区每行有显式结果（`conversion-rules.md` §13.5/§13.7）；不满足 → 停下逐条追问，不进入执行。
- 通过后按作答词表逐条执行：同意 → 按建议；需要调整 → 按「说明」中的替代方案（说明缺失 → 停下问该条）；本次跳过 → 该项不落地并记去向。执行完更新执行台账状态，可追加“→已落地（日期）”审计标记。

### 收尾分支（你决定下一步，用固定口令）
- 回复 **「按清单落地」** → 进入阶段三（闸门 2 先展示逐文件改动方案）。
- 回复 **「先修订候选 / 清单」** → agent 修订后重新停在闸门 1。
- 回复 **「先不落地」** → 流程结束：仓库只留清单与候选，`data/` 零改动。
- 任何一步想暂停 → 直接说 **「先等等」**，agent 就地停止等待。

## 阶段三 · 落地（landing：经批准才允许写数据）

### 1. 闸门 2 · 改动方案确认闸（写入前）

#### 摆逐文件 diff 草稿
- `data/events.json`：仅追加本 skill 命名空间事件，既有条目零改动。
- `data/scenes.json`、`data/items.json`、`data/meta.json`：如涉及，逐处单列（坐标 / 素材 / 物品注册 / 入口均属设计输入）。

#### 逐文件确认后才写入
- 用户逐文件确认改动方案 → 才按白名单写入（`conversion-rules.md` §11）；未确认不写入。

### 2. 写入与真实编译
- 写入后于真实仓库运行 `node tools/compile-data.mjs`；报错即回滚已写入改动、修复后重跑，不蒙混。

### 3. 闸门 3 · 终审闸（提交前）
- 汇报：改动文件清单、diff 摘要、编译结果；已执行清单条目追加“→已落地（日期）”标记。
- 用户终审通过 → 按仓库规范做中文、原子、详细的 git 提交（如 `feat(skills):…`、`docs(剧本):…`）。
- 未通过 → 退回闸门 2（或闸门 1）。
- 任何一步用户要求“先等等”：就地停止等待；提交必须以终审为前置条件。

## 验收（每次运行结束自查）

### 产物校验
- 候选 JSON：全部 ID 合法且唯一；无悬空引用；只引用已注册属性 / 场景；`node -e "JSON.parse(...)"` 可解析。
- 审查清单：执行台账覆盖每个事件中的不可直译检定、SAN、前提 / 条件、物品获得、素材依赖、表现指令、文本疑点；正文为每条需要拍板者生成人话提问（一条一问）；素材指定区逐行有素材类型、状态与所需形态。

### 红线复核
- 无任何未经逐条答复（同意 / 需要调整）的推断落地；无任何素材未经审阅者显式指定（沿用 / 新建 / 委托占位补位 / 暂缓并注明影响）即被依赖落地；输入剧本文件未被改动；`data/*.json` 与编译产物未被写；`schemas/`、`src/`、`tools/` 未被写；`assets/` 仅新增两类文件（委托占位 SVG / 自 `Assets/` 复制的图片副本）、未改写既有文件；源目录 `Assets/` 严格只读、未被改动。

### 汇报要点
- 清单路径、待办概览（N 条提问、M 行素材）与通过条件校验结果；若已落地：diff 摘要与真实编译结果；未推送的提交提醒。

## 与用户交互的注意事项

对用户给予充分的引导。
如果你在阀门处有任何 **预期收到的固定词语** 作为指令，应该主动列举出来，并简单解释，以供用户选择。闸门 1 停点至少列举：

- 每条提问的可勾选项：**同意 / 需要调整 / 本次跳过**（需要调整时请给替代方案）；
- 每行素材的可选项：**沿用 / 新建（命名 + 内容描述）/ 本行暂缓（注明影响）**；
- 收尾口令：**已修改，继续 / 按清单落地 / 先修订候选 / 先不落地 / 先等等**。
