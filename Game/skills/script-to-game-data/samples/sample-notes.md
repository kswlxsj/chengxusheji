# 样例说明

本样例演示“节选剧本 → 候选 JSON”的转换结果，配套文件：

- `sample-input.md`：节选（E-001~E-008、E-012~E-014），逐字摘自 `Assets/Text/剧本.md`；
- `sample-output.json`：按 `conversion-rules.md` 转换得到的候选事件（命名空间 `E_0NN`）。

> 展示口径：下文以“转换分析口径”叙述（如“登记为自动推断 / 类别 A”），对应现行审查清单中的**执行台账**记录；审阅者在清单正文看到的是由此生成的人话提问与素材指定，展示格式见 `templates/review-checklist-template.md` 与 `conversion-rules.md` §13。

## 2. 关键转换决策示范（与 `conversion-rules.md` 条文对应）

1. **检定新写法（§6.1）**：可直译检定输出 `{ "type": "check", "dice": "<编号>", "outcomes": [成败片段…] }`；标准属性检定用 dice.js 工厂 `attrCheck("<属性>")`（1d6＋属性 ≥ 11，0=成功/1=失败）。
2. **SAN 记法（§7，约定 C1）**：`SAN X/Y` → SAN 检定，dice 条目 = `sanCheck("san", <成功损失>, <失败损失>)`；损失（整数或 `{ count, sides }` 骰子规格）从原文直译、由 dice 函数扣减，事件内不再写任何扣损动作。
3. **无分支副作用形态（§6.2）**：成败两侧叙事与去向一致（E-006A/B、E-014）→ `check` 不带 `outcomes`，扣损在 dice 函数内完成，事件靠 `next`/场景返回收尾，不再为“无事发生侧”造空端点事件。
4. **需新增 dice 条目（§6.1/§11）**：`ev001_insight_01`、`ev004_insight_01`、`ev014_san_01` 未注册 → 登记执行台账（类别 C，落点 `src/dice.js`），落地经闸门 2 逐条确认后追加一行工厂调用；`ev005_insight_01`、`ev006a_san_01`、`ev006b_san_01` 已注册 → 直接引用。
5. **前置变体拆分（§8）**：E-005 灵感成败直接决定 E-006 的 SAN 变体，把 E-006 拆为 `E_006A`（0/1）与 `E_006B`（1/1d4），避免运行时旗标路由。
6. **占位行（§9）**：技能检定（医学/侦查/急救/话术）无法落地，事件内放原文整行占位（如“（检定：医学）”），分支文本不转录，只进审查清单。占位行是原文转录、非发明文本，人工落地后删除。
7. **说话人（§5）**：“（乘务员）正文”前缀提出后映射到 `speaker`；正文逐字保留。
8. **舞台指令（§5）**：（场景：抖动）（音效：惊悚凌厉）（场景：一半变黑）纯指令不入 JSON，登记类别 F；（主角表情：惊恐）这，这是什么！为“指令+正文”，整行原样转录。
9. **choice prompt（§5）**：剧本只有“（选择：…）”行无问句原文，`prompt` 置空串并在清单登记（不发明提示语）。
10. **场景动作**：E-006 位于 7 号车厢 → 在变体入口用 `changeScene`（引用既有真实场景 `carriage_07` 以便通过隔离编译）；其它车厢（4 号等）尚无真实场景，登记类别 E/H。

## 3. 本样例的边界（勿误解为成品）

- **切片外引用**：`E_009`（E-005 放弃项、E-008 尾跳）与 `E_017`（E-013 失败线）属于节选外事件，样例内**故意保留悬空引用**以展示结构；隔离编译验证时会注入临时 stub（空动作事件），仅存在于临时目录。
- **新 dice 编号**：`ev001_insight_01`、`ev004_insight_01`、`ev014_san_01` 在真实 `src/dice.js` 中未注册，隔离编译验证时在临时副本内追加占位注册行（`registerDice("<编号>", attrCheck("<属性>"))` / `sanCheck(...)`），仅存在于临时目录；落地时按 §11 经闸门 2 逐条确认后才追加到真实文件。
- `E_014` 在本节选内无入口事件（其入口是 E-013 苏醒线），为“孤儿事件”，编译可通过但暂不可达——真实落地需由 E-013 接线。
- E-005/E-006 车厢推进的真实热点物件（门/尸体/深处）需要场景与坐标，见审查清单 E/H 节。
- `E_008` 的侦查成败分支文本与 SAN 1/1d6 因技能不可检定而只在清单 C 节。
- 涉及“可重复调查/检定一次或多次”等触发拓扑问题全部留在清单 H 节，不擅自决定。
