# 剧本转换 skill 使用教程（从触发后开始）

> 适用对象：在 webGame 仓库内操作本转换 skill 的人与执行 agent（两边对照阅读）。
> 前置：skill 已被触发（你已说出类似“用剧本转换 skill 把 X 剧本转一下”并得到回应）；**本教程不涉及如何安装/如何触发**。
> 权威规则：`skills/script-to-game-data/SKILL.md`（红线与闸门）与 `skills/script-to-game-data/转换规范.md`（全部细节）；策略见 `config/policy.json`。本教程是“走一遍”的手把手指引，冲突时以 SKILL.md 与转换规范.md 为准。

## 0. 总览：一次完整转换的三段闸门

```text
你指定输入文件
   ▼
[候选阶段] 解析剧本 → 候选JSON(不落盘) + 审查清单落盘(分钟时间戳) + 隔离编译验证
   ▼
闸门 1（决策闸）→ agent 停下，你逐项决策清单 A~I；决定是否落地
   ▼
闸门 2（改动方案确认闸）→ agent 摆逐文件 diff 草稿，你逐文件确认
   ▼
[landing] 写入白名单 JSON → 真实 npm run compile（报错即回滚修复）
   ▼
闸门 3（终审闸）→ 你看 diff 与编译结果；通过后 agent 才 git 提交
```

任何闸门未获你明确批准，agent 必须就地等待，不得跳过或把两闸合并。

---

## 1. 第 0 步：先把“输入”说清楚（你触发后的第一次对话）

agent 会按规矩**先确认输入**，你不给文件它不会开工：

- 你只需回答输入文件路径（一个或多个），例如：`把 Assets/Text/剧本.md 转一下`；
- 多文件时顺带说明关系：连载（第 1 卷、第 2 卷？）、不同版本（以哪份为准？）、各自独立（分属不同剧本？）；
- 如果你忘了给，agent 会列出候选并问你“用哪个 / 还是放弃”，你选一个即可。

agent 校验失败（文件不存在、不是 UTF-8、内容不是剧本）时会停下报告，不会硬转。

## 2. 候选阶段（agent 自动完成，你不用干预）

agent 依次做（顺序详见 SKILL.md 工作流）：

1. 只读注册表快照：`data/attributes.json`、`data/skills.json`、`data/items.json`、`data/scenes.json`、`data/events.json`；
2. 按 `转换规范.md` 语法表逐事件解析，产出**候选 JSON 片段**（默认不写盘，用于与你确认）；
3. **审查清单落盘**：`Game/docs/剧本转换审查/剧本转换审查清单-YYYY-MM-DD-HHmm.md`（目录固定、时间戳精确到分钟、每次新建不覆盖；示例：`剧本转换审查清单-2026-09-04-1849.md`）；
4. **隔离编译验证**：把 `Game/` 复制到系统临时目录 → 注入候选 → 跑 `node tools/compile-data.mjs` → 断言通过后删除临时目录（真实 `data/` 全程不动）。

想提前熟悉产物长什么样？看 `skills/script-to-game-data/samples/`：`样例输入.md`（节选原文）、`输出样例.json`（候选事件）、`样例说明.md`（逐条解释每个语法怎么映射、哪些进了清单）。

## 3. 闸门 1：你的决策环节（最关键的人机交接）

候选阶段结束，agent 会停在第 1 闸门并汇报：清单路径、覆盖事件数、待决项概览。此时你打开清单逐节处理：

| 节 | 你要做的事 | 花的时间 |
| --- | --- | --- |
| A 转换范围 | 扫一眼：确认输入、覆盖事件、命名空间没跑偏 | 1 分钟 |
| B 自动推断登记 | 审约定 C1~C5 与推断 D1~D2：同意就留着，不同意直接推翻让 agent 改方案 | 数分钟 |
| C 检定与规则语义 | **重点**：每个技能检定/对抗/%修正怎么落地，逐条拍板或写“由框架组处理”（F 节挂钩） | 最长 |
| D 物品与数值 | 钥匙/手机/报纸要不要注册成物品、id 叫什么、%修正换算 | 中 |
| E 素材与场景 | 场景/物件/贴图对照表是否有异议（坐标由美术另填） | 中 |
| F 框架能力缺口 | 转交给框架维护者，确认不阻塞本次落地范围 | 几分钟 |
| G 文本问题 | 你是编剧：确认 E-019/E-022 是否笔误、说话人标注风格 | 几分钟 |
| H 触发拓扑 | **重点**：每条路线通不通、可否重复调查、卡死路径怎么解 | 较长 |
| I 下一步 | 决策顺序建议 | — |

做法：直接在对话里把决策说给 agent（它会把清单“状态”列从“待人工”更新为你的决定，**另开新文件或修订旧文件由你指定**，默认每次转换新建）。

三种收尾方式：
- “就按清单 C~H 的决定落地” → 进入闸门 2；
- “先把 X 节改成……” → agent 修订候选/清单后重新停下；
- “先不落地” → 到此为止，仓库只有清单与候选，无任何数据改动。

## 4. 半路提问：agent 什么时候会打断你（阻断情形）

这些不是流程故障，是 skill 的规矩（转换规范.md §16）——碰到就停下问你，**不猜**：

- 跳转目标不存在：如“（→E-01X）”查无此事件 → 你确认是笔误还是漏写事件；
- 编号冲突：来源编号和既有 events.json 或另一输入文件撞车 → 你给命名空间或改编号；
- 分支归属无法判定、内容语义不明 → 你拍板；
- 落地要求超出白名单或要删除既有内容 → 你要先明确授权；
- 表格/特殊结构无法映射 → 转人工，别硬编。

示例：
> agent：E-009 的“分支2 失败”之后没有跳转，若侦查失败会拿不到报纸线索、流程可能卡死（清单 H4）。我停在闸门 1 前等你的决定：允许失败后重试 / 失败也放行但错过信息 / 其他？
> 你：失败后仍可继续到 E-010，但拿不到日期线索（对应分支文本不触发）。

## 5. 闸门 2：逐文件确认改动方案

你批准落地后，agent 先把 **diff 草稿**摆出来，而不是直接写：

- `events.json`：检查点——只追加新命名空间事件；旧条目零改动；占位行位置符合你批准的方案；无悬空引用；
- `scenes.json` / `items.json` / `meta.json`：只在你要改时才出现 diff，且每个改动都要你单独点头（涉及坐标/素材/物品注册等设计输入，skill 无权自作主张）。

你可以逐文件说“events 的追加块确认”“scenes 这版不改”“items 的钥匙 id 改成 crew_keys 再确认”。全部确认后 agent 才执行写入。

## 6. landing：写入与真实编译

- agent 把候选写入白名单文件（保持 2 空格缩进风格）；
- 在**真实仓库**执行 `node tools/compile-data.mjs`（等价 `npm run compile` 的核心）；报错即回滚修复重跑，不允许蒙混过关；
- 如需跑测试可再执行 `npm test`（视改动面）。

## 7. 闸门 3：终审与提交

写入并编译通过后，agent 汇报：改动文件清单、diff 摘要、编译输出、审查清单状态。你终审：

- 满意 → 说“可以提交”；agent 按仓库规范做**中文、原子、详细**的 git 提交（示例：`feat(skills): …`、`docs(剧本): …`）；
- 不满意 → 指出问题，退回闸门 2（改方案重写）。

注意：即使 agent 已写盘，**git 提交仍以你的终审为前置条件**；你随时喊停，agent 就地等待。

## 8. 一次成功跑完，你应该拿到什么

- 一份审查清单：`docs/剧本转换审查/剧本转换审查清单-<时间戳>.md`（本次转换的决策台账）；
- （若你批准落地）白名单 JSON 的追加 diff 与真实编译通过结果；
- 一次（或多次）中文原子 git 提交记录；
- 输入剧本文件原样未动；`data/attributes.json`/`skills.json`/`schemas/`/`src/`/`tools/` 等全程未被写。

## 9. 常见问题（FAQ）

**Q：审查清单会不会把旧的覆盖掉？**
不会。文件名带分钟级时间戳且每次新建；同名剧本再转会得到一份新文件。要修订旧清单，需你明确指定文件，agent 才会在原文件增量修改并在文件头注明修订记录。

**Q：候选 JSON 为什么不写盘？**
候选是“未定稿的半成品”，写进 `data/` 会造成既有内容区与未定内容的混乱。它只用于与你确认；确认后经闸门 2 才作为 diff 进入白名单文件。

**Q：清单里的“占位行”是什么样，怎么变成真规则？**
形如事件里一条 `{ "type": "dialogue", "text": "（检定：医学）" }`——原文照录、表示此处待人工落地。落地时你给出规则（如映射到某属性+修正，或注册技能），agent 替换为真正的 `check`/其他动作并删除占位行。

**Q：和既有 events.json 里那套 E_CHECK_* / 演示事件什么关系？**
skill 默认只增不改不删，也绝不自动判断旧区段去留；关系处置（保留/替换/清理/成为主线）在落地前由你决定（见审查清单 H1）。

**Q：为什么会有 `actions: []` 的空事件？**
“检定某侧无事发生、事件自然结束回场景”时的端点约定（转换规范 §6.2）；编译器和运行时都接受。详见样例 `E_006A_END`。

**Q：隔离编译和真实编译有什么差别？**
隔离编译在临时副本里跑，验证“候选合入后全量无悬空/无重复”；真实编译在落地写盘后跑。先隔离是为了在动真实数据前发现问题。

**Q：多文件剧本怎么办？**
先说明关系。连载用同一编号体系时把编号冲突交给你的命名空间决定；版本并列以你指定为准；互相引用跨文件的跳转视同悬空询问。

**Q：什么时候会跑 `npm run check`？**
落地修改涉及测试面时，终审前跑一遍更稳妥；只出清单不落地则不需要。

## 10. 出问题时的兜底

- 不确定就问 agent，让它引 SKILL.md/转换规范对应小节；
- 任何一步你想反悔：在闸门 1/2 直接说“退回上一步”，agent 会还原候选或回滚已写入改动（写入未提交前均可回滚到工作区原状）；
- 记住三条底线：**不写注册表、不改 schema/运行时、不发明数值**——清单里永远能找到“为什么这里没自动转”的答案。
